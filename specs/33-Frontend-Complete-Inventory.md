## How to read this file

1. **Stack and entry points** — what the app is built with and where it starts.
2. **Route map** — every URL the app serves, the file that serves it, who may open it, and the spec that explains the screen.
3. **Guards and redirects** — the rules that send people away from a page.
4. **Feature folders** — each `src/features/<area>` folder and the spec that owns it.
5. **Shared foundations** — components, UI primitives, hooks, helpers, schemas, integrations.
6. **Full file inventory** — every source file, its main exports, and the spec that cites or owns it. The "Cited in spec" column shows `(owner)` where no spec names the file; the owner column is the spec that covers it.

Route paths are the URLs a browser sees. The `_app` prefix in a file name is a layout marker and does not appear in the URL.

## Guards and redirects

| Rule | Where | What happens |
|---|---|---|
| Signed-in only | `_app.tsx` → `requireAuthSession` (`features/auth/route-guards.ts`) | If the session is missing, the visitor is sent to `/login` with a `redirect` search param cleaned by `sanitizeRedirect`. |
| Signed-in visitors leave the login page | `login.tsx` → `redirectAuthenticatedUser` | A signed-in visitor is sent to the `redirect` target (or `/`). |
| Role-restricted areas | `_app.configuration.tsx`, `_app.user-management.tsx` → `requireAllowedRoles(auth, ['super_admin','admin'])` | Any other role, or no user, is redirected to `/`. |
| Queue access inside a component | `_app.cases.work-queue-cases.tsx`, `_app.cases.ep-sub-merchants.tsx` | Access is checked in the component, not in `beforeLoad`, so every visit does not show the loading skeleton. A user without work access is sent to `/cases/all-cases`. |
| Old URL redirects | `_app.configuration.index.tsx` → `limits-and-mdr`; `_app.configuration.email-sending.tsx` → `email-templates`; `_app.merchants.$merchantId.index.tsx` → `overview`; `_app.configuration.email-templates.index.tsx` → a template key (from `?template=` or the first) | Redirects use `replace: true`. |
| Not-found | `__root.tsx` `notFoundComponent` | Unknown URLs render the not-found page. Malformed route params (not UUIDs or tokens) render not-found through `parseUuidParam` / `parseTokenParam` in `src/lib/route-params.ts`. |

> ⚠️ Role checks in the browser are a convenience. The backend enforces the same roles on every API call (see files 03 and 29).
